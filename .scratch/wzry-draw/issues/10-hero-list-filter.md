# 10 — 英雄池页英雄列表分路筛选

**What to build:** 英雄池页两处英雄列表（页面底部「全部英雄」浏览网格、「编辑成员」弹层选人清单）各增加一组按分路的 tab 筛选：全部 / 对抗路 / 打野 / 中路 / 发育路 / 游走，默认选中「全部」。多分路英雄出现在其所属的每个分路分类中（如廉颇＝对抗路＋游走，两个 tab 都能看到）。两处 tab 互相独立；弹层内切换筛选不丢失已勾选状态。

**涉及页面/文件：** `app/pages/pool.vue`（两处列表与筛选交互）、`app/utils/`（分路筛选纯函数）、`test/`（对应单测）。

## 验收结论（2026-09-29）

**结论：全部验收项通过；代码审查 APPROVE（无阻塞项，P2 一条已修）。**

### 逐条结论

1. **两处 tab 与独立性**：通过。底部浏览网格与「编辑成员」弹层各有独立的 `LaneFilterTabs`（`browseLane` / `memberLane`），默认均为「全部」；实测把浏览列表切到「打野」后打开弹层、在弹层切到「中路」再关闭，浏览列表仍为「打野」。
2. **过滤正确性与多分路归属**：通过。六个分路计数与数据完全一致（全部 133 / 对抗路 44 / 打野 50 / 中路 31 / 发育路 20 / 游走 34，合计 179 = 分路标签总数）；每个分路结果内均含该分路且**无重复**；多分路英雄在每个所属分路各出现一次（廉颇 对抗路×1 + 游走×1、钟无艳 对抗路×1 + 打野×1、墨子 中路×1 + 游走×1、亚瑟 对抗路×1 + 打野×1）。
3. **计数口径**：通过。浏览列表计数跟随筛选（「全部」=133 位，切分路后为 44/50/31/20/34）；弹层保持「已选 X / 133」全量口径，切分路不变（实测切到对抗路后仍为「已选 2 / 133」）。
4. **勾选保持与打开重置**：通过。弹层内勾选 2 个 → 切「对抗路」（已选仍 2、廉颇仍勾选）→ 再勾 1 个（已选 3）→ 切回「全部」，三个勾选全部保留；「取消」后重开回到「全部」且改动被丢弃；「保存」后重开显示已保存的勾选且筛选为「全部」。
5. **纯函数与单测**：通过。`app/utils/heroes.ts` 的 `filterHeroesByLane` 与 UI 解耦；`test/heroes.test.ts` 覆盖「全部返回全量且为新数组」「按分路过滤正确」「多分路英雄归属多个分路」「结果数之和等于分路标签总数」「单分路英雄只出现在自己的分路」「空列表」「不修改入参」，全仓 52 项单测通过。
6. **响应式**：通过。375px 下 6 个 tab 以 3 列两行铺开、全部在视口内（每个 44px 高、约 98~109px 宽），页面 `scrollWidth` = 375 无横向滚动；768px 与 1440px 下自动变为一行、无退化（1440 下内容仍为 768px 限宽居中）。其他四个页面无筛选组、无横向滚动。
7. **视觉与对比度**：通过。选中态为金色胶囊（金底 + 金描边 + 金字），未选中为中性描边；实测对比度：浅色选中 4.67:1、未选中 10.36:1，深色选中 7.89:1、未选中 10.49:1，均达 WCAG AA。
